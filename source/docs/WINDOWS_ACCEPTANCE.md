## 稳定性实验设计

后端：`scripts/soak.ps1 -Seconds 3600`，读取实际 samples、错误列表、进程内存/句柄/CPU轨迹，和结束退出码。1秒设置下应有约3600个样本，但实际查询耗时/后台降频可能减少；不能只按数量认定成功。

完整GUI：至少1小时，记录每5秒整个进程树 CPU/Private Bytes/Working Set/句柄；前10分钟正常，之后重复切换11页/改变采样间隔/暂停恢复，期间断开测试网卡一次后恢复（确保不会断开远程控制连接）、拒绝一次联网确认、测试一个不存在的 DNS 名称（有明确授权后）、取消一次硬件刷新。不要修改或破坏 WMI 服务来制造失败；在隔离测试配置/虚拟机或可注入错误的测试构建中模拟提供程序失败。

退出后观察主进程、属于本应用的 WebView2 子进程和查询 PowerShell 进程，不得随意结束其他程序的同名进程。数据不足、残留、卡死、异常峰值都要记录，不为了达到目标删除异常区间。

## 性能测量口径

冷启动目标 <3s、热启动 <1.5s、空闲 CPU <1%、完整进程树内存 <150MB、页面切换 <200ms 是目标，不是当前实测值。

冷启动须注明机器重启/缓存条件、Runtime预热/更新状态、磁盘及安全软件；从用户启动到主界面可用结束，至少5次，记录每次与中位数/P95。热启动在同环境重复；不能将Go端口已监听时间代替UI可用时间。CPU观察60秒以上，说明是单逻辑核100%还是整机归一化口径；WebView2多进程与临时PowerShell计入总资源。高DPI和最小化状态分开测量。
